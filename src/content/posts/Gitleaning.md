# Git
- 首先要明确概念
    - 一个本地的git仓库本质是一个文件夹，在这个文件夹内初始化git仓库，出现一个.git隐藏文件夹就表示本地仓库建成了

- 它的底层整体式分三个区的
    - 工作区：可以理解为当前的文件夹的内容，包括当前修改的任何内容
    - 暂存区：文件修改后用add从工作区添加进这个暂存区，可以理解为一个临时的存储区
    - 本地仓库：用commit把暂存区的内容提交到本地仓库

- 远程仓库：一般来说，为了让项目上线，就不可能只让他存在本地仓库，所以存在远程仓库这一东西，它可以是服务器，但我们的日常使用更多是github或者gitee等

## 基础的git命令
|命令|说明|
|--|--|
|git init					|（初始化仓库）|
|git status					|（查看暂存区）|
|git log					|（查看日志：查看 commit 记录）|
|git add 文件名				|（添加文件进暂存区）|
|git add .					|（添加工作区所有文件进暂存区）|
|git commit -m "注释"		|（提交暂存内容进仓库）|
|git reset --hard commitID	|（回退到某个提交过的版本，但是在那个普通的 log 看不到回退前的版本之后的 commit 记录了，但可以通过 git reflog 查看所有历史操作找到 commitID，并执行 git reset --hard commitID 再次回退 / 回退）|

## 分支：
|命令|说明|
|--|--|
|git branch			|（查看分支）|
|git branch 分支名		|（创建分支名）|
|git checkout -b 分支名	|（切换并创建分支）|  

## 补充
如果有些文件不希望被识别提交，可以创建一个名为 .gitignore 文件，文件内用 * 文件名 或 *. 文件后缀，来使 git 不去识别这些文件。

## 合并：
|命令|说明|
|--|--|
|git merge 分支名|（将这个分支合并到当前分支）|

## 删除分支
|命令|说明|
|--|--|
|git branch -d 分支名|（不能删当前分支，只能删其它分支，小写d会检查，不会直接删除）|
|git branch -D 分支名|（大写的d会直接删除）|

## 冲突
- 在合并时，有可能会发生冲突，比如在两个分支对同一文件的同一行做了不同的修改时，去合并就会有冲突，
此时，合并冲突后的该文件会标出两边修改的区别，我们对该文件做修正后再 commit 就可以解决。

## 规范：
- master 主分支：正式上线，长期运行的
- develop 开发分支：新功能会写在这，最后合并
- feature 功能分支：作为 develop 分支的细分分支，可理解为，小的业务块会写在这，最后合并到 develop 中，可删除。
- hotfix 分支：用于专门修 bug 的分支

## git远程仓库的连接
- 主流有两种方式
    - 1，HTTPS + PAT 个人令牌，这个方式在fork别人的代码生成副本，然后clone下来的时候会用到，只需跟着指引做就行
    - 2，用SSH公钥，在本地cmd执行
    ```git
    ssh-keygen -t ed25519 -C "你的平台绑定邮箱"
    ```
会生成密钥和配套公钥，他会默认存在C:\Users\你的用户名\.ssh\
复制对应公钥，粘贴进远程仓库的SSH设置里即可


- 而而本地也要对每个本地的git仓库做远程仓库的连接才行
命令
```git
git remote add <远程仓库名称><仓库路径(这个路径从网站建立仓库获得，可能是类似网址的格式)>
```

## 远程推送命令

git push [--set-upstream][远端名称[本地分支:远端分支]]（只有第一次推送的时候要写全，他的基本意义是这样，前面的--set-upstream表示固定后面的仓库对应关系，带上它以后就不用再完整的格式，而是git push即可，而后面的表示推送到远端的仓库，本地的分支与远端的分支对应去提交）

## 克隆
git clone<仓库路径> [本地文件夹目录]
tips：克隆下来的项目会自动关联仓库和设置对应分支

## 抓取和拉取
- 抓取：将远程仓库更新到本地，但不进行合并（很少用）
	git fetch
- 拉取：将远程仓库更新到本地，并进行合并（其实就是fetch后merge了）
	git pull

**所以综上，多人开发时，我们通常都先pull一遍，再本地解决冲突后，再去push提交**
